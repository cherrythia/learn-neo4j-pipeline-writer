# ADR-0011: API key for ingestion; admin login with roles

- Status: Accepted
- Date: 2026-11-12

## Context
Admin actions must be protected and attributed; full SSO is not needed yet.

## Decision
Ingestion routes require `X-API-Key`. The admin UI uses a local login with a hashed password and a JWT in an httpOnly cookie, with roles `admin` and `reviewer`. Secrets live in `.env`.

## Consequences
Simple to run. SSO (Azure AD, Keycloak) can replace the login later.

## Update (issue #13)
Passwords use stdlib `scrypt`. CSRF is handled by `SameSite=Lax` plus a required
`X-Requested-With: writer-admin` header on every state-changing cookie request (enforced in
`current_user`). Unset API key means ingestion is refused. Sessions are revocable through a
per-user `session_version`. Logins are throttled per username+client and per client.
Production refuses weak JWT secrets, insecure cookies and weak ingest keys. See
[`docs/auth.md`](../auth.md).
